\subsection{Correlation Analysis with numeric data}
The \g{correlation coefficient}, also called \g{Pearson's product-moment coefficient}, is defined as
\[
    r_{A,B} = \frac{\sum_{i=1}^{n}(a_i-\bar{A})(b_i-\bar{B})}{n\sigma_A\sigma_B}
\]

where $n$ is the number of tuples, $\bar{A}$ and $\bar{B}$ are the mean values of the attributes A and B. $\sigma_A$ and $\sigma_B$ are 
the standard deviations of the attributes A and B. 

\begin{itemize}
    \item If $r_{A,B}>0$, then A and B are positively linearly correlated.
    \item If $r_{A,B}<0$, then A and B are negatively linearly correlated.
    \item If $r_{A,B}=0$, then there is no linear correlation between A and B (this does not mean that they are independent, see the remark below).
\end{itemize}

For visualization of the correlation between two attributes we can use a scatter plot and see the trend of the points.

The same coefficient can be computed without centering the data first, using the sum of the cross-products $a_ib_i$ (for each tuple we multiply the value of A by the value of B):
\[
    r_{A,B} = \frac{\sum_{i=1}^{n}(a_ib_i)-n\bar{A}\bar{B}}{n\sigma_A\sigma_B}, \qquad -1 \leq r_{A,B} \leq +1
\]
The closer $|r_{A,B}|$ is to 1, the stronger the linear relation between the two attributes. This is why we compute it during data integration: a high value tells us that one of the two attributes carries almost the same information as the other and may be removed as redundant.

\begin{remark}
We need to be careful with the case $r_{A,B}=0$. The Pearson coefficient only detects \s{linear} relationships: if the points lie on a parabola, B is completely determined by A and still $r_{A,B}=0$. So $r_{A,B}=0$ means that there is no linear correlation between A and B. If A and B are independent then $r_{A,B}=0$, but the converse is not true in general: it holds only under additional assumptions, for example when the data follow a multivariate normal distribution.

Also, correlation does not imply causality. For example the number of hospitals and the number of car thefts in a region are correlated, but neither causes the other: both depend on a third attribute, the population.
\end{remark}

\subsubsection{Covariance}
Covariance is a measure similar to correlation: both tell us how much two numeric attributes change together.

\begin{definition}[Covariance]
Given two numeric attributes A and B and $n$ observations $(a_1,b_1),\dots,(a_n,b_n)$, with mean (expected) values $\bar{A}=\E(A)$ and $\bar{B}=\E(B)$, the covariance between A and B is
\[
    \Cov(A,B) = \E\big((A-\bar{A})(B-\bar{B})\big) = \frac{\sum_{i=1}^{n}(a_i-\bar{A})(b_i-\bar{B})}{n}
\]
It can also be computed as
\[
    \Cov(A,B) = \E(A\cdot B) - \bar{A}\bar{B}
\]
which is often easier to use in the calculations.
\end{definition}

The correlation coefficient is the covariance divided by the two standard deviations, so it is a covariance that does not depend on the scale of the attributes:
\[
    r_{A,B} = \frac{\Cov(A,B)}{\sigma_A\sigma_B}
\]

\begin{itemize}
    \item $\Cov(A,B)>0$: A and B tend to be above (or below) their expected values together.
    \item $\Cov(A,B)<0$: when one attribute is above its expected value, the other tends to be below.
    \item $\Cov(A,B)=0$: this does not always imply independence. If A and B are independent then $\E(A\cdot B)=\E(A)\cdot\E(B)$ and the covariance is 0, but there are pairs of attributes with covariance 0 that are not independent.
\end{itemize}
The variance is the special case of the covariance of an attribute with itself: $\Var(A)=\Cov(A,A)$.

\begin{example}[Covariance of two stock prices]
We observe the prices of two stocks at five time points: $A = (6,5,4,3,2)$ and $B = (20,10,14,5,5)$. We want to know if they rise and fall together.
\[
    \E(A) = \frac{6+5+4+3+2}{5} = 4, \qquad \E(B) = \frac{20+10+14+5+5}{5} = 10.8
\]
\[
    \Cov(A,B) = \frac{6\cdot 20+5\cdot 10+4\cdot 14+3\cdot 5+2\cdot 5}{5} - 4\cdot 10.8 = 50.2-43.2 = 7
\]
The covariance is positive, so the two prices tend to rise together.
\end{example}

\subsection{Data reduction}

To reduce the data size we can work in different ways:
\begin{itemize}
    \item \g{Dimensionality reduction}: reduce the number of attributes, for example by removing redundant or irrelevant attributes.
    \item \g{Numerosity reduction}: reduce the number of tuples, for example by sampling or aggregation, or by replacing the objects with models.
    \item \g{Data compression}: reduce the data size by encoding the data more efficiently.
\end{itemize}

Why should we reduce the number of dimensions? We need to avoid the \g{curse of dimensionality}, a phenomenon that occurs when the number of dimensions increases and that has three effects:
\begin{itemize}
    \item \g{Sparsity}: the data become increasingly sparse and the density becomes less meaningful.
    \item \g{Distances}: the distance between points becomes less meaningful, because all the points appear far from each other when the space is too sparse. This is a problem because almost all the algorithms in machine learning are based on distance or density.
    \item \g{Combinations}: the possible combinations of subspaces grow exponentially with the number of dimensions, so visualization becomes difficult and the time and space requirements increase.
\end{itemize}

Besides avoiding the curse of dimensionality, reducing the number of dimensions helps us to eliminate irrelevant features, reduce noise, reduce the time and space required by the mining algorithms and make visualization easier.

To reduce dimensionality we see two different approaches:
\begin{itemize}
    \item \g{Linear projection methods} (e.g. PCA, Principal Component Analysis): we transform the data and then work with the transformed data.
    \item \g{Heuristic methods}: we use greedy methods directly on the data source.
\end{itemize}

\subsection{Principal Component Analysis (PCA)}

In PCA we want to find the directions of maximum variance in the data and project the data onto these directions. 
\begin{itemize}
    \item Step1: Calculate Adjusted Data Matrix: we center the data by subtracting the mean of each attribute from the data points.
    \item Step2: Calculate Covariance Matrix from adjusted Data.
    \item Step3: Calculate Eigenvalues and Eigenvectors of the covariance matrix. If the eigenvalues are 0 or really small we can discard them and their corresponding eigenvectors.
    \item Step4: Transform the data onto the new basis formed by the relevant eigenvectors. $F=E^TA$ where $F$ is the transformed data set, $E$ is the matrix of eigenvectors and $A$ is the adjusted data matrix.
\end{itemize}

More precisely, we are given $N$ data vectors in $f$ dimensions and we look for $k \leq f$ orthogonal vectors, the \s{principal components}, that can best be used to represent the data. We see the steps again with the formulas.

\begin{itemize}
    \item Before starting we normalize the input data, so that all the attributes are on comparable ranges. Otherwise the attributes with a large domain have the largest variance and dominate the others. PCA works only with numeric data.
    \item Step1: we write the data set as a matrix $D$ with $f$ rows (dimensions) and $N$ columns (data samples). $M$ is the vector of the means, where $M_i$ is the mean of the values in dimension $i$. The adjusted data set is $A = D - M$, where $M_i$ is subtracted from all the values of row $i$. Now every dimension of $A$ has mean 0.
    \item Step2: the covariance matrix $C$ is a $f \times f$ matrix where $C_{ij}$ is the covariance between dimension $i$ and dimension $j$ (on the diagonal we find the variances):
    \[
        \Cov(X,Y) = \frac{\sum_{i=1}^{N}(X_i-\bar{X})(Y_i-\bar{Y})}{N-1}
    \]
    Since the means of the dimensions in $A$ are 0, we can compute the whole matrix at once:
    \[
        C = \frac{AA^T}{N-1}
    \]
    \item Step3: the eigenvectors of $C$ are the columns of the matrix $E$ and they are the axes of the new space. Each eigenvalue is the variance of the data along the corresponding eigenvector, so we sort the components by decreasing eigenvalue: the first axis shows the most variance, the second axis the next highest variance, and so on. Discarding the components with the smallest eigenvalues reduces the dimensionality of the new basis and we lose little information.
    \item Step4: if we keep only $k$ eigenvectors in $E$, then $F=E^TA$ has $k$ rows instead of $f$: the dimensions of the new data set are less than the ones of $A$. To recover $A$ from $F$ we use the fact that $E$ is orthogonal, so $E^{-1}=E^T$:
    \[
        (E^T)^{-1}F = (E^T)^{-1}E^TA \quad\Longrightarrow\quad EF = A
    \]
    If we discarded some components, $EF$ is only an approximation of $A$, but a good one if the discarded components were weak.
\end{itemize}

\begin{remark}
In the covariance matrix of PCA the slides divide by $N-1$, while in the definition of covariance seen before we divide by $n$. For a large number of samples the difference is negligible.
\end{remark}

\begin{example}[Covariance matrix for PCA]
We have $N=5$ people, each one described by Height, test Score and Age, so $f=3$.
\begin{center}
\begin{tabular}{lrrrrrr}
\toprule
 & S1 & S2 & S3 & S4 & S5 & Mean \\
\midrule
Height & 64 & 66 & 68 & 69 & 73 & 68 \\
Score & 580 & 570 & 590 & 660 & 600 & 600 \\
Age & 29 & 33 & 37 & 46 & 55 & 40 \\
\bottomrule
\end{tabular}
\end{center}
We subtract the mean from each row and compute variances and covariances, for example
\[
    \Var(\text{Height}) = \frac{(-4)^2+(-2)^2+0^2+1^2+5^2}{5-1} = \frac{46}{4} = 11.5
\]
\[
    \Cov(\text{Height},\text{Score}) = \frac{(-4)(-20)+(-2)(-30)+0\cdot(-10)+1\cdot 60+5\cdot 0}{5-1} = \frac{200}{4} = 50
\]
Repeating the computation for all the pairs we obtain the covariance matrix
\[
    C = \begin{pmatrix}
        11.5 & 50 & 34.75 \\
        50 & 1250 & 205 \\
        34.75 & 205 & 110
    \end{pmatrix}
\]
where rows and columns are in the order Height, Score, Age. The variance of Score is much larger than the others only because of its scale: this is why we should normalize the data before applying PCA.
\end{example}

PCA is an unsupervised approach, because we do not use any information about the class labels of the data points. PCA is also a transformation method, because we transform the data into a new basis formed by the eigenvectors that are different features from the original ones.

This is the main difference with subset selection, that we see next: subset selection keeps some of the original attributes, PCA instead combines all of them to create a smaller set of new variables. Each principal component is a linear combination of the original attributes, so the new features are harder to interpret, and PCA is a linear method: it works well when the structure of the data is approximately linear, it becomes ineffective when it is not.

\subsection{Subset selection}
A second way to reduce dimensionality is to select a subset from the original features. We need to select only the features relevant to our task, trying to avoid redundancy and irrelevance. We can't try every possible subset of features to find the best one, we need to use a greedy approach.

We will see two different approaches to select a subset of features:
\begin{itemize}
    \item \g{Forward selection}: we start with an empty set of features and we add one feature at a time, selecting the most relevant and least redundant feature at each step.
    \item \g{Backward elimination}: we start with the full set of features and we remove one feature at a time, removing the least relevant and most redundant feature at each step.
\end{itemize}
For both approaches we need a metric to define relevancy and redundancy.

In detail, the attributes we want to remove are of two kinds:
\begin{itemize}
    \item Redundant attributes: they duplicate much or all of the information contained in other attributes. For example the purchase price of a product and the sales tax paid.
    \item Irrelevant attributes: they contain no information useful for the mining task. For example the student ID when we want to predict the GPA.
\end{itemize}
Keeping irrelevant attributes (or leaving out relevant ones) can confuse the mining algorithm and give patterns of poor quality, and the extra volume slows down the mining. Working on fewer attributes also makes the discovered patterns easier to understand.

With $d$ attributes there are $2^d$ possible subsets, this is why an exhaustive search is not feasible. A greedy method always makes the choice that looks best at the moment (a locally optimal choice), hoping that this leads to a globally good solution. It is not guaranteed to find the optimal subset, but in practice it works well.

\begin{example}[Forward selection and backward elimination]
The initial set of attributes is $\{A_1,A_2,A_3,A_4,A_5,A_6\}$.

Forward selection: $\{\} \rightarrow \{A_1\} \rightarrow \{A_1,A_4\} \rightarrow \{A_1,A_4,A_6\}$. At each iteration we test the remaining features and we add the one with the best score.

Backward elimination: $\{A_1,A_2,A_3,A_4,A_5,A_6\} \rightarrow \{A_1,A_3,A_4,A_5,A_6\} \rightarrow \{A_1,A_4,A_5,A_6\} \rightarrow \{A_1,A_4,A_6\}$. At each iteration we discard the feature whose removal hurts least.
\end{example}

A good subset is not just made of individually strong features: each feature should add information without duplicating what is already selected. A typical way to score a candidate feature $A_j$ given the set $S$ of the features already selected is
\[
    \text{score}(A_j \mid S) = \text{relevance}(A_j, \text{target}) - \text{redundancy}(A_j, S)
\]
In forward selection we add the feature with the maximum score, in backward elimination we remove the feature with the lowest marginal contribution. The procedure stops when a stopping criterion is met, for example a threshold on the measure or a fixed number of features.

Other heuristic methods are:
\begin{itemize}
    \item Combination of forward selection and backward elimination: at each step we select the best attribute and we remove the worst among the remaining ones.
    \item Decision tree induction: we build a decision tree on the data; the attributes that do not appear in the tree are assumed to be irrelevant, the ones that appear form the reduced subset.
    \item The best and worst attributes can also be chosen with tests of statistical significance (that assume the attributes independent of one another) or with measures like the information gain. The slides also name branch and bound among the search strategies.
\end{itemize}

\subsubsection{An example of heuristic: NMIFS}
An example of forward selection is NMIFS (Normalized Mutual Information Feature Selection, by Est\'evez, Tesmer, Perez and Zurada, 2009). We need to be careful: this method needs the ground truth, because the relevance of a feature is measured with respect to the class labels.

\begin{definition}[Mutual information]
Given two discrete variables $X$ and $Y$ with alphabets $\mathcal{X}$ and $\mathcal{Y}$ (the sets of their possible values), joint probability mass function $p(x,y)$ and marginal probabilities $p(x)$ and $p(y)$, the mutual information between $X$ and $Y$ is
\[
    I(X,Y) = \sum_{x\in\mathcal{X}}\sum_{y\in\mathcal{Y}} p(x,y)\cdot\log\frac{p(x,y)}{p(x)p(y)}
\]
\end{definition}

If $X$ and $Y$ are independent then $p(x,y)=p(x)\cdot p(y)$, every logarithm is 0 and so $I(X,Y)=0$. The sum runs over all the possible combinations of values: for example if $X$ is the age with values \{young, medium, old\} and $Y$ is the output with values \{class1, class2, class3\}, we need the nine probabilities $p(\text{young},\text{class1})$, $p(\text{young},\text{class2})$, \dots, $p(\text{old},\text{class3})$.

The problem is: given an initial set $F$ with $n$ features, find the subset $S \subset F$ with $k$ features that maximizes the mutual information $I(C;S)$ between the class variable $C$ and the selected features. NMIFS uses the mutual information for both terms of the score:
\begin{itemize}
    \item Relevance: $I(C;f_i)$, the mutual information between the class and the feature $f_i$.
    \item Redundancy: the average normalized mutual information between $f_i$ and the features already selected, where
    \[
        NI(f_i;f_s) = \frac{I(f_i;f_s)}{\min\{H(f_i),H(f_s)\}}
    \]
    and $H$ is the entropy. The normalization compensates for the bias of the mutual information toward features with many values and restricts the values to the range $[0,1]$.
\end{itemize}
At each step we select the feature that maximizes
\[
    G = I(C;f_i) - \frac{1}{|S|}\sum_{f_s\in S} NI(f_i;f_s)
\]

The algorithm is:
\begin{enumerate}
    \item Initialization: $F=\{f_i \mid i=1,\dots,N\}$ is the initial set of $N$ features and $S=\emptyset$.
    \item Compute the mutual information with respect to the classes, $I(f_i;C)$, for each $f_i\in F$.
    \item Select the first feature $\hat{f}_i = \argmax_{i=1,\dots,N} I(f_i;C)$. Set $F \leftarrow F\setminus\{\hat{f}_i\}$ and $S \leftarrow \{\hat{f}_i\}$.
    \item Greedy selection, repeated until $|S|=k$:
    \begin{enumerate}
        \item compute the mutual information between features, $I(f_i;f_s)$, for all the pairs with $f_i\in F$ and $f_s\in S$;
        \item select the feature $\hat{f}_i\in F$ that maximizes $G$. Set $F \leftarrow F\setminus\{\hat{f}_i\}$ and $S \leftarrow S\cup\{\hat{f}_i\}$.
    \end{enumerate}
    \item Output the set $S$ of the selected features.
\end{enumerate}


\subsection{Attribute creation / feature generation}
Sometimes the features we need are not in the original data, so we need to create new ones. We can create features in three different ways:
\begin{itemize}
    \item \g{Extraction}: transformation specific to the domain, for example we can extract features from images or text, or map the data to a new space.
    \item \g{Construction}: we can combine existing features to create new ones, for example a new feature that is the sum of two existing features.
    \item \g{Discretization}: we can convert continuous features into discrete ones.
\end{itemize}

Typical examples of mapping the data to a new space are the Fourier transformation and the wavelet transformation. For construction, a classic example is adding the attribute \s{area} computed from the attributes \s{height} and \s{width}: the new attribute makes explicit a relation between the original ones that the mining algorithm may not find alone, and it is still interpretable. Discretization, that we see at the end of this lesson, also reduces the data size and prepares the data for the methods that work with categories.

\begin{remark}
The discrete wavelet transform (DWT) can also be used to reduce the data. It transforms a data vector into a vector of wavelet coefficients of the same length, but we can store only the strongest coefficients (for example the ones above a threshold) and set the others to 0. We obtain a sparse, compressed approximation of the data, that can be rebuilt applying the inverse transform. Compared to the Fourier transform, with the same number of coefficients the DWT usually gives a more accurate approximation, and wavelets are localized in space so they preserve local details.
\end{remark}

\subsection{Numerosity reduction}
We can reduce the number of stored values by choosing optimal representation. We need to be careful because we can lose information: smaller data often means higher speed and lower cost, but also lower accuracy. We need to preserve the data structure and the relevant information. We can use two families of methods:
\begin{itemize}
    \item Parametric methods: We assume that the data fit a models and we compute, and only store, the parameters of the model. For example, we can use linear regression to fit a line to the data and use the parameters of the line to represent the data.
    \item Non-parametric methods: we do not assume any specific distribution for the data, but we use techniques that are based on the data itself to find families or aggregations. For example, we can use histograms or kernel density estimation to model the data.
\end{itemize}
There is a trade-off between compression and detail: smaller representations can be faster, but they may hide local structure. The right method depends on the query and on the mining task.

\subsubsection{Parametric methods}
With regression we replace many observations with a fitted function: we estimate the parameters of the model, we store only them and we discard the raw data (except possible outliers).

\texttt{Linear regression:} the data are modeled to fit a straight line
\[
    y = w_1x + w_0
\]
The two regression coefficients $w_1$ (slope) and $w_0$ (intercept) define the line and are estimated from the data with the least squares criterion, that is we choose the line that minimizes the sum of the squared errors between the known values $y_i$ and the values predicted by the line. If $|D|$ is the size of the data set and $\bar{x}$, $\bar{y}$ are the means:
\[
    w_1 = \frac{\sum_{i=1}^{|D|}(x_i-\bar{x})(y_i-\bar{y})}{\sum_{i=1}^{|D|}(x_i-\bar{x})^2}, \qquad w_0 = \bar{y}-w_1\bar{x}
\]

\begin{example}[Linear regression]
For five students $x_i$ is the score on the aptitude test and $y_i$ is the statistics grade.
\begin{center}
\begin{tabular}{crrrrrr}
\toprule
Student & $x_i$ & $y_i$ & $x_i-\bar{x}$ & $y_i-\bar{y}$ & $(x_i-\bar{x})^2$ & $(x_i-\bar{x})(y_i-\bar{y})$ \\
\midrule
1 & 95 & 85 & 17 & 8 & 289 & 136 \\
2 & 85 & 95 & 7 & 18 & 49 & 126 \\
3 & 80 & 70 & 2 & $-7$ & 4 & $-14$ \\
4 & 70 & 65 & $-8$ & $-12$ & 64 & 96 \\
5 & 60 & 70 & $-18$ & $-7$ & 324 & 126 \\
\midrule
Sum & 390 & 385 & & & 730 & 470 \\
Mean & 78 & 77 & & & & \\
\bottomrule
\end{tabular}
\end{center}
\[
    w_1 = \frac{470}{730} = 0.6438, \qquad w_0 = 77 - 0.6438\cdot 78 = 26.78
\]
The regression equation is $y = 0.6438x + 26.78$: instead of the five pairs we store only two numbers.
\end{example}

\texttt{Multiple linear regression:} the response variable is modeled as a linear function of a multidimensional feature vector, for example with two attributes
\[
    y = w_0 + w_1x_1 + w_2x_2
\]
The coefficients are still found with least squares. In matrix form, if $X$ is the matrix of the observations (with a first column of 1s for the intercept $w_0$) and $Y$ the vector of the responses:
\[
    W = (X^TX)^{-1}X^TY
\]

\texttt{Non-linear regression:} many non-linear functions can be transformed into the linear form above. For example the polynomial regression
\[
    y = w_0 + w_1x + w_2x^2 + w_3x^3
\]
becomes linear if we define the new variables $x_1=x$, $x_2=x^2$, $x_3=x^3$:
\[
    y = w_0 + w_1x_1 + w_2x_2 + w_3x_3
\]
and it can be solved with the methods of multiple regression.

\texttt{Log-linear models:} they approximate discrete multidimensional probability distributions. They are useful for smoothing and for reduction.

\subsubsection{Non-parametric methods}
\begin{itemize}
    \item Histograms: we divide the data into buckets and we store the frequency of each bucket. We can use equi-width or equi-depth histograms.
    \item Clustering: we group the data into clusters, by similarity, and we store the cluster centroids. We can use k-means or hierarchical clustering.
    \item Sampling: we select a subset of the data and we store only the selected data points. We can use random sampling or stratified sampling.
\end{itemize}

Some details on the three families.

\texttt{Histograms:} a histogram partitions the values of an attribute into disjoint ranges called buckets (or bins). For each bucket we store only a summary, like the count, the average or the sum of its values. If a bucket represents a single value with its frequency it is called a singleton bucket (useful to store high-frequency outliers); to reduce the data more, each bucket represents a continuous range. In an equi-width histogram all the buckets have the same range width, in an equi-depth (equal-frequency) histogram each bucket contains roughly the same number of samples.

\texttt{Clustering:} for each cluster we store only its representation, the centroid and the diameter. It is effective if the data are really organized in clusters, it is less effective if the data are smeared.

\texttt{Sampling:} we represent the whole data set of $N$ tuples with a small sample of $s$ tuples. The advantage is that the cost of obtaining the sample is proportional to $s$ and not to $N$, so a mining algorithm can run with a complexity that is potentially sub-linear in the size of the data, while other reduction techniques need at least one complete pass through the data. Simple random sampling may fail if the data are skewed, stratified sampling improves the representation.

We can have sampling with replacement or without replacement. The common ways to sample a data set $D$ of $N$ tuples are:
\begin{itemize}
    \item Simple random sample without replacement (SRSWOR) of size $s$: we draw $s$ tuples from $D$, every tuple has the same probability to be chosen, and a drawn tuple is removed from $D$, so it can not be drawn again.
    \item Simple random sample with replacement (SRSWR) of size $s$: as before, but after a tuple is drawn it is recorded and then placed back in $D$, so it may be drawn again.
    \item Cluster sample: if the tuples of $D$ are grouped into $M$ mutually disjoint clusters, we take a simple random sample of $s$ clusters, with $s<M$. For example tuples in a database are retrieved a page at a time, so each page can be a cluster.
    \item Stratified sample: $D$ is divided into mutually disjoint parts called strata and we draw a sample from each stratum, proportionally to its size. It is useful when the data are skewed, because also the small groups are still represented. For example, with one stratum for each age group of the customers, the group with the fewest customers is sure to be represented.
\end{itemize}

The key difference between sampling with and without replacement is whether the draws are independent. Consider a finite population of size $N$ with variance $\sigma^2 = \frac{1}{N}\sum_i (x_i-\mu)^2$ and let $X_1$, $X_2$ be the first and the second draw.
\begin{itemize}
    \item With replacement: after the first draw the population is restored, so the first draw does not affect the probabilities of the second one. $X_1$ and $X_2$ are independent and $\Cov(X_1,X_2)=0$.
    \item Without replacement: after the first draw one value has been removed, so the first draw changes what can happen in the second. $X_1$ and $X_2$ are negatively dependent:
    \[
        \Cov(X_1,X_2) = -\frac{\sigma^2}{N-1}
    \]
    Intuitively, if the first value is high, fewer high values remain. The covariance is small when $N$ is large.
\end{itemize}

\subsubsection{Aggregation and compression}
\begin{itemize}
    \item Data cube aggregation: also aggregation is a way to reduce the data. The base cuboid stores the data at the lowest level, and we can aggregate at multiple levels: for example from the sales per quarter we compute the sales per year. We use the smallest representation that is sufficient for the task, and we answer the aggregate queries with the cube when possible.
    \item Lossless compression: the original data can be reconstructed from the compressed data without any loss of information. It is typical of string compression, where there are well-tuned theories and algorithms, but only a limited manipulation of the data is possible without expanding it.
    \item Lossy compression: we can reconstruct only an approximation of the original data. It is typical of audio and video compression, often with progressive refinement, and sometimes small fragments of the signal can be reconstructed without rebuilding the whole. Time sequences are not like audio: they vary slowly with time.
\end{itemize}
Dimensionality reduction and numerosity reduction can also be considered forms of data compression.

\subsection{Transformation}

The last step in data pre-processing is transformation, which is the process of changing the format, structure or values of the data. We have three different families of transformations:
\begin{itemize}
    \item \g{Smoothing}: removing noise.
    \item \g{Aggregation \& construction}: create new attributes from existing ones.
    \item \g{Normalization \& discretization}: scale values to a smaller range.
\end{itemize}

\g{Data normalization}. These techniques are applied to ensure a more efficient and accurate data analysis. Normalization brings all the values into a specific range, to ensure that an attribute isn't more important just because of its higher scale.

We can see the problem in the computation of the Euclidean distance between two points $p$ and $q$ with $n$ attributes:
\[
    d(p,q) = \sqrt{(q_1-p_1)^2+(q_2-p_2)^2+\dots+(q_n-p_n)^2} = \sqrt{\sum_{i=1}^{n}(q_i-p_i)^2}
\]
If the first attribute has range 0--1000000 and the others have range 0--1, the first term is predominant and the distance depends practically only on it. The same happens when we change the unit of measure: expressing an attribute in smaller units gives it a larger range and so a larger weight. For this reason normalization is needed by the methods based on distances (nearest-neighbor classification, clustering), and it also speeds up the learning phase of neural networks.

\texttt{min-max normalization:} we rescale the data to a specific range, usually [0,1]. We can use the formula:
\[
    v' = \frac{v-v_{min}}{v_{max}-v_{min}}(new\_max - new\_min)+new\_min
\]
where $v_{min}$ and $v_{max}$ are the minimum and maximum values of the attribute and $[new\_min,\allowbreak new\_max]$ is the new range. It is a linear transformation, so it preserves the relationships among the original values. The problem is that if a future value falls outside the original range $[v_{min}, v_{max}]$, it is mapped outside the new range (an ``out-of-bounds'' error).

\begin{example}[Min-max normalization]
The income ranges from \$12,000 to \$98,000 and we normalize it to $[0.0, 1.0]$. The value \$73,600 is mapped to
\[
    \frac{73{,}600-12{,}000}{98{,}000-12{,}000}(1.0-0)+0 = 0.716
\]
\end{example}

\texttt{z-score transformation}: Use mean and standard deviation and the distance increase using number of standard deviations as scale. 
\[
    v' = \frac{v - \mu_A}{\sigma_A}
\]
This normalization works well with outliers, which are instead a problem for min-max.
It is also the one to use when the actual minimum and maximum of the attribute are unknown.

\begin{example}[z-score normalization]
With $\mu_A = 54{,}000$ and $\sigma_A = 16{,}000$ the income \$73,600 is transformed to
\[
    \frac{73{,}600-54{,}000}{16{,}000} = 1.225
\]
\end{example}

A variation replaces the standard deviation with the mean absolute deviation of A
\[
    s_A = \frac{1}{n}\big(|v_1-\mu_A|+|v_2-\mu_A|+\dots+|v_n-\mu_A|\big), \qquad v' = \frac{v-\mu_A}{s_A}
\]
that is more robust to outliers than $\sigma_A$, because the deviations from the mean are not squared.

\texttt{Decimal scaling}: we move the comma in the number depending on the max absolute values of the attribute.
\[
    v' = \frac{v}{10^{j}}
\]
where $j$ is the smallest integer such that $\max(|v'|)<1$.

\begin{example}[Decimal scaling]
The values of A range from $-986$ to $917$, so the maximum absolute value is 986. We divide each value by 1000 ($j=3$): $-986$ becomes $-0.986$ and $917$ becomes $0.917$.
\end{example}

\begin{remark}
Normalization can change the original data quite a bit, especially with z-score and decimal scaling. We also need to save the parameters used (for example mean and standard deviation for the z-score), so that future data can be normalized in the same way.
\end{remark}

\subsubsection{Discretization}
With discretization we divide the range of a continuous attribute into intervals, and the interval labels (for example 0--10, 11--20, or conceptual labels like \s{youth}, \s{adult}, \s{senior}) replace the actual values. We do it to reduce the data size and to prepare the data for classification, because some algorithms work only with categorical attributes. We recall the types of attributes: nominal (unordered categories, like the color), ordinal (ordered categories, like the rank) and numeric (integer or real numbers).

The methods differ in two aspects:
\begin{itemize}
    \item Supervised vs. unsupervised: a method is supervised if it uses the class labels to choose the intervals, unsupervised otherwise.
    \item Top-down (splitting) vs. bottom-up (merging): a top-down method first finds one or a few split points (cut points) that divide the whole range, and then repeats recursively on the resulting intervals. A bottom-up method starts by considering all the values as potential split points and removes some of them by merging neighboring values into intervals, again recursively.
\end{itemize}
The typical methods are binning and histogram analysis (unsupervised, top-down split), clustering analysis (unsupervised, top-down or bottom-up), correlation / $\chi^2$ analysis (supervised, bottom-up merge) and the entropy-based methods (supervised, top-down split).

\texttt{Unsupervised discretization: binning.} We choose the number $N$ of intervals and one of two partitioning rules:
\begin{itemize}
    \item Equal-width partitioning: we divide the range into $N$ intervals of equal size (a uniform grid). If $A$ and $B$ are the lowest and the highest values of the attribute, the width of the intervals is
    \[
        W = \frac{B-A}{N}
    \]
    It is the most straightforward method, but outliers may dominate the presentation and skewed data are not handled well.
    \item Equal-depth (equal-frequency) partitioning: we divide the range into $N$ intervals, each containing approximately the same number of samples. It scales well with the data and handles skewed data better.
\end{itemize}
Binning does not use the class information and it is sensitive to the number of bins chosen by the user and to the presence of outliers. Histogram analysis works in the same way, with the buckets seen for numerosity reduction. Both can be applied recursively to the resulting partitions to generate a hierarchy of intervals.

\begin{example}[Binning]
Sorted prices: 4, 8, 9, 15, 21, 21, 24, 25, 26, 28, 29, 34. Binning can also be used to smooth the sorted values.
\begin{center}
\begin{tabular}{llll}
\toprule
Method & Bin 1 & Bin 2 & Bin 3 \\
\midrule
Equal-frequency bins & 4, 8, 9, 15 & 21, 21, 24, 25 & 26, 28, 29, 34 \\
Smooth by bin means & 9, 9, 9, 9 & 23, 23, 23, 23 & 29, 29, 29, 29 \\
Smooth by boundaries & 4, 4, 4, 15 & 21, 21, 25, 25 & 26, 26, 26, 34 \\
\bottomrule
\end{tabular}
\end{center}
\end{example}

\texttt{Clustering.} We can also discretize by clustering the values of the attribute and using one interval for each cluster. Clustering looks at the distribution of the data, so for example k-means may give better intervals than naive binning: in the comparison on the slides equal-width and equal-frequency binning cut through the natural groups of points, while k-means separates them.

\texttt{Supervised discretization.} Here the intervals are chosen taking the class labels into account, so that they are useful for classification. Doing the discretization during the learning can be expensive for big data, so we use heuristic approaches with specific metrics to choose the cut points.

\texttt{ChiMerge.} It is a bottom-up method based on the $\chi^2$ test. $F$ is the numeric feature and $K$ the class label.
\begin{enumerate}
    \item We sort the records by $F$ and we start from maximum detail: one interval for each distinct value of $F$, using as cut points the midpoints between consecutive values.
    \item For each pair of adjacent intervals we build the contingency table (the two intervals on the rows, the classes on the columns) and we compute
    \[
        \chi^2 = \sum_{i}\sum_{j}\frac{(O_{ij}-E_{ij})^2}{E_{ij}}, \qquad E_{ij} = \frac{(\text{total of row } i)\cdot(\text{total of column } j)}{N}
    \]
    where $O_{ij}$ are the observed counts, $E_{ij}$ the counts expected under independence and $N$ the number of samples in the two intervals. The null hypothesis is that the class is distributed in the same way in the two intervals: a small $\chi^2$ means that there is no strong evidence that the two intervals differ, a large $\chi^2$ that they behave differently.
    \item We merge the pair of adjacent intervals with the smallest $\chi^2$, if it is below the critical value. With two classes we have 1 degree of freedom, and with significance level $\alpha=0.10$ the critical value is about 2.71.
    \item We recompute $\chi^2$ only for the new adjacent pairs and we repeat. We stop when no adjacent pair has $\chi^2$ below the critical value.
\end{enumerate}
ChiMerge is greedy, and it merges only adjacent intervals because the discretization must preserve the order of the values of $F$. The intervals become as coarse as possible while still preserving the changes that depend on the class: fewer intervals are simpler, but too much merging loses class information.

\begin{example}[ChiMerge]
We have 12 samples with $F = 1, 3, 7, 8, 9, 11, 23, 37, 39, 45, 46, 59$ and class $K = 1, 2, 1, 1, 1, 2, 2, 1, 2, 1, 1, 1$. The initial cut points are the midpoints $2, 5, 7.5, 8.5, 10, 17, 30, 38, 42, 45.5, 52$, that give 12 intervals between 0 and 60.

Two examples of the test. For the intervals containing the samples 2 and 3 (classes 2 and 1) every cell of the table has expected count 0.5, while the observed counts are 0 or 1: each of the four cells contributes $\frac{(0.5)^2}{0.5}=0.5$, so $\chi^2 = 4\cdot 0.5 = 2$. For the intervals containing the samples 3 and 4 (both of class 1) the expected counts are equal to the observed ones, so $\chi^2=0$.

\begin{itemize}
    \item First pass: the adjacent intervals with the same class have $\chi^2=0$ and are merged first. We obtain $[0,2)$, $[2,5)$, $[5,10)$, $[10,30)$, $[30,38)$, $[38,42)$, $[42,60]$, with $\chi^2$ between neighbors equal to $2, 4, 5, 3, 2, 4$.
    \item The two pairs with $\chi^2=2<2.71$ are merged: $[0,5)$, $[5,10)$, $[10,30)$, $[30,42)$, $[42,60]$, with $\chi^2$ equal to $1.875, 5, 1.333, 1.875$.
    \item The smallest value is 1.333: we merge $[10,30)$ and $[30,42)$. Now we have $[0,5)$, $[5,10)$, $[10,42)$, $[42,60]$ with $\chi^2$ equal to $1.875, 3.938, 3.938$.
    \item We merge $[0,5)$ and $[5,10)$. The remaining values are $2.723$ and $3.938$, both above 2.71, so we stop.
\end{itemize}
The final bins for $F$ are $[0,10)$, $[10,42)$ and $[42,60]$, that contain respectively 4, 1 and 3 samples of class 1 and 1, 3 and 0 samples of class 2.
\end{example}

\texttt{Fayyad and Irani approach.} It is a supervised, top-down method based on the entropy. For each continuous attribute $A$ we look for the best set of cut points, evaluating the candidates with the class entropy.

We do not need to test every possible real value: the optimal cut points lie between two adjacent sorted examples of different classes. So we sort the examples by $A$ and we consider only the boundary points.

\begin{definition}[Boundary point]
A potential cut point $T$ is a boundary point if it lies between two adjacent examples $e_1$ and $e_2$ of different classes, with $A(e_1) < T < A(e_2)$. Usually $T$ is the midpoint. $B_A$ is the set of the candidate boundary points for the attribute $A$.
\end{definition}

\begin{definition}[Class entropy]
Let $S$ be a set of examples with $k$ classes $C_1,\dots,C_k$ and let $P(C_i,S)$ be the proportion of examples of $S$ that have class $C_i$. The class entropy of $S$ is
\[
    E(S) = -\sum_{i=1}^{k} P(C_i,S)\log_2 P(C_i,S)
\]
\end{definition}

The entropy measures the uncertainty on the class: it is close to 0 when the subset is pure and it is high when the classes are mixed. A cut point $T$ splits $S$ into $S_1$ (the examples with $A\leq T$) and $S_2$ (the examples with $A>T$), and the class information entropy of the partition is the weighted average
\[
    EP(A,T;S) = \frac{|S_1|}{|S|}E(S_1)+\frac{|S_2|}{|S|}E(S_2)
\]
The best cut point $T_A$ is the candidate with the minimum $EP(A,T;S)$, the one that reduces the uncertainty the most.

The algorithm is recursive: we split $S$ at the best cut point $T_A$, then we apply the same procedure to $S_1$ and $S_2$. We continue only while the split is worth its complexity. The information gain of the cut is
\[
    G(A,T_A;S) = E(S) - EP(A,T_A;S)
\]
and, by the MDL (minimum description length) principle, the cut is accepted only if
\[
    G(A,T_A;S) > \frac{\log_2(|S|-1)+\Delta(A,T_A;S)}{|S|}
\]
otherwise we stop. $\Delta(A,T_A;S)$ is a correction term that penalizes the discretizations that are too complex:
\[
    \Delta(A,T_A;S) = \log_2(3^c-2) - \big[c\,E(S) - c_1E(S_1) - c_2E(S_2)\big]
\]
where $c$, $c_1$, $c_2$ are the numbers of classes represented in $S$, $S_1$, $S_2$.
% Delta: the slide (3.Preprocessing.pdf, slide 98) prints it truncated ("log2(3c) - c1 E(S1) - c2 E(S2))").
% The formula above is verified on the original paper (Fayyad and Irani, 1993, IJCAI-93, pp. 1022--1027, Sec. 3.3), where the number of classes is called k instead of c.

\texttt{Concept hierarchy generation.} A concept hierarchy organizes the values of an attribute hierarchically, and we reduce the data by replacing the low-level values with higher-level concepts: for example the numeric ages become \s{youth}, \s{adult}, \s{senior}. In a data warehouse this allows us to view the data at multiple granularities (drill-down and roll-up). The hierarchy can be specified by the experts or formed automatically, both for numeric data (applying the discretization methods recursively) and for nominal data, for example street $<$ city $<$ state $<$ country, or \{Urbana, Champaign, Chicago\} $<$ Illinois. For nominal attributes the automatic generation can use the number of distinct values of each attribute.
